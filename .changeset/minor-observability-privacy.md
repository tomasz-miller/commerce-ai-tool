Opt-in debug logging, PII mask and Langfuse sessions. Verbose search tracing (`logSearchTrace`) and the per-step `meta.timings` in search responses now turn on only with `CAT_DEBUG=true`; `NODE_ENV` no longer enables it, so hosts that never set `NODE_ENV=production` (such as an Express BFF started with `node`) stop printing queries and commercetools request bodies. Shopper text in trace lines is logged as length and hash unless the new `CAT_DEBUG_RAW=true` is also set. The always-on production error line of `logServerError` now includes the API error code and redacts quoted values, e-mail addresses and phone numbers from the message; the full message is logged with `CAT_DEBUG=true`. A 503 `UPSTREAM_UNAVAILABLE` is logged at warn level in every environment (4xx are not logged), and `logServerWarning` no longer depends on `NODE_ENV`. New `defaultLangfuseMask` (exported from `@commerce-ai-tool/server` and `@commerce-ai-tool/server/flush`) redacts e-mail addresses and phone-number-like digit runs in everything exported to Langfuse (JSON input and output strings are parsed and stay valid JSON; hex hashes and model ids are left alone); pass it as `mask` to `LangfuseSpanProcessor`. Text queries are exported to Langfuse on the `ai.interpret*` generations, so the text-search request span now records only `queryLength` and `refineQueryLength` instead of the query. Search requests accept an optional `widgetSessionId` (1 to 200 characters of `A-Za-z0-9._:-`, invalid values are dropped) that is propagated as the Langfuse `sessionId` (new `withTraceSession`, in `@commerce-ai-tool/core/internal`). The image redaction hash now covers the full image and equals the hash on the request span. The Angular demo BFF registers the Langfuse exporter and flushes it on SIGTERM and SIGINT.

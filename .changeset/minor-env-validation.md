Environment configuration is validated at boot. `loadConfigFromEnv()` now throws `Invalid <NAME>: ...` for a set but invalid numeric or enum variable (`CAT_AI_PROVIDER`, `CAT_VOICE_MODE`, `CAT_DEFAULT_LIMIT`, `CAT_CACHE_TTL_MS`, `CAT_CACHE_MAX_ENTRIES`, `CAT_MISSIONS_MAX_INTENTS`, `CAT_MISSIONS_PER_INTENT_LIMIT`, `CAT_MISSIONS_MIN_CONFIDENCE`, `CAT_FACET_SCHEMA_TTL_MS`, `CAT_FACET_MAX_ATTRIBUTES`, `LANGFUSE_PROMPT_CACHE_TTL_SECONDS`) instead of passing NaN or an unknown value through; a non-numeric `CAT_CACHE_MAX_ENTRIES` used to disable cache eviction. Numeric values must be positive integers (`CAT_MISSIONS_MIN_CONFIDENCE` 0 to 1; `CAT_CACHE_TTL_MS` and `LANGFUSE_PROMPT_CACHE_TTL_SECONDS` also accept 0, where `CAT_CACHE_TTL_MS=0` still means no cache); empty means unset. `CAT_CACHE_MAX_ENTRIES` is only parsed when the cache is enabled, and now also applies with `CAT_CACHE_ENABLED=true`. Hosts with a typo in these variables, including a previously ignored `LANGFUSE_PROMPT_CACHE_TTL_SECONDS`, will now fail at startup. `SearchCache` falls back to 500 entries for a non-finite or non-positive `maxEntries`.

`CAT_MISSIONS_ENABLED=false` now maps to `missions: { enabled: false }`, the hard opt-out. New `CartSessionConfig` / `CommerceAIConfig.cartSession.secret`: `loadConfigFromEnv()` fills it from `CAT_CART_SESSION_SECRET`, and `createCommerceAIServer` no longer reads that variable itself (the commercetools client secret is no longer a fallback signing key since 3.0.0, see the major changeset). `ELEVENLABS_STT_MODEL` is honoured: `scribe_v2` (default), `scribe_v1`, `scribe_v2_medical` and `scribe_v3`; an unknown value logs a warning and uses `scribe_v2`.

`CAT_SUPPORTED_LOCALES` constrains catalog locales only. `queryLocale` (the shopper's language) now only needs to be a canonical BCP 47 tag and falls back to the resolved `catalogLocale` when invalid, so a `pl-PL` shopper is no longer relabelled on an `en-GB,de-DE` catalog. Allowlist entries are canonicalised once at startup; invalid entries (for example `en_GB`) are dropped with a warning, and a set `CAT_SUPPORTED_LOCALES` (or `supportedLocales`) in which no entry is valid fails at startup with `Invalid CAT_SUPPORTED_LOCALES` instead of silently accepting every locale. docs/CONFIGURATION.md lists every environment variable with its default.

Every error the widgets show now comes from `messages`, never from the server's or the browser's text. The cart panels (React and Angular) no longer rewrite the English strings `Invalid credentials` / `Sign in failed` / `Login failed`; they render the already localized error they are given, and the Angular `displayCartError` helper is removed (it was not exported from the package entry). An error also shows when the search box is empty: a failed image search or camera capture used to show nothing.

Accessible names now say which product they act on. New optional message keys, with English defaults, each with a `{name}` placeholder: `addToCartNamed` ("Add {name} to cart"), `removeItemNamed` ("Remove {name} from cart") and `quantityFor` ("Quantity of {name}"). A host that translated `addToCart` or `removeItem` but not the new keys gets `"<its text>: <product name>"`, so its own language is kept. The add-to-cart buttons (search and mission results) and the cart remove button use them; the quantity buttons sit in a `role="group"` named by `quantityFor`, and the quantity value is a `role="status"`, so a change is announced. **Accessible names changed:** selectors that match the exact names "Add to cart" or "Remove item" no longer find the buttons (they are now "Add Running shoe to cart", "Remove Running shoe from cart"), and a product-name substring match such as `getByRole("button", { name: "Running shoe" })` now hits the select button and the add button; anchor it (`/^Running shoe/`). The quantity buttons are now inside a `role="group"`. Core exports `formatNamedMessage`, `addToCartLabel`, `removeItemLabel` and `quantityGroupLabel`.

The voice button in both widgets no longer sets `aria-pressed`: its name already changes ("Voice search" / "Stop recording"), and a button must not announce both a changing name and a pressed state. The empty and failed mission-lane blocks are no longer `role="status"`; the widget's live region announces them.

React `CommerceAICheckout` and `CommerceAIOrderStatus` no longer render a `<main>` by default, so they fit inside the host's own `<main>`. They accept `as?: "main" | "section" | "div"` (default `"section"`, named by the widget title), `headingLevel?: 1 | 2 | 3` (default `2`; sections follow one level below) and `renderLink?: (props: { href: string; className: string; children: ReactNode }) => ReactNode` for router-aware links (default: a plain `<a>` with the same `href` and `className`). **DOM change for existing hosts:** the root was a `<main>` with an `<h1>` title and `<h2>` section headings; it is now a `<section>` with an `<h2>` title and `<h3>` sections (`<h4>` for the billing address). Pass `as="main"` and `headingLevel={1}` to keep the same elements and heading levels (the root also gains `aria-labelledby` and the title gains an `id`). The stylesheet no longer styles these headings by tag, so the look does not change with the level.

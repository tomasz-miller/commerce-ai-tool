The Angular widget works in zoneless hosts (the default from Angular 21, `provideZonelessChangeDetection()`), in `OnPush`-default hosts and under `OnPush` parents, with no `zone.js` polyfill. Before, async results (text search without autocomplete, image search) and the "added all" confirmation left the UI stuck in hosts that did not run change detection after every task. All components are `OnPush`, state is held in signals, and the manual `detectChanges()` calls are gone. Selectors, input and output names and accepted input types are unchanged.

Fixes in the same rework: pressing Enter now cancels the pending suggestions timer and request; image and voice searches carry an `AbortSignal` and a request id, so a slower image or voice response no longer overwrites a newer text search, and an aborted request shows no error; destroying the widget stops the microphone stream and recorder (also when `getUserMedia` resolves after destroy), aborts requests, clears timers and stops audio; choosing the same image twice works again (the file input is reset); the voice upload is labelled with the container the browser recorded instead of always `audio/webm`; the spoken summary is played from a blob instead of a base64 data URL. Facet chips send `facetSelections` only for groups the shopper clicked (filters the model echoed back are not chips), like the React widget.

The Angular HTTP and cart code now run on the shared browser client of `@commerce-ai-tool/core/client`: `CommerceAiApiService` methods keep their signatures (`searchByImage`, `searchByVoice` and `synthesizeSpeech` gain a trailing optional `signal`) and now reject with `CommerceAIApiError`; `CommerceAiCartService` shares the page-wide cart session store, mutation queue and cart sync with other Angular widgets and with host code that imports the same `@commerce-ai-tool/core/client` module instance (the React package bundles its own copy, so a React and an Angular widget on one page do not share a store), and takes an optional `messages` in `configure()`. Errors the widget shows (search, image, voice, camera, cart) now come from the `messages` input instead of server or browser text. Component state is now held in internal signals, and every public member of `CommerceAiSearchComponent`, `CommerceAiMissionResultsComponent` and `CommerceAiCartPanelComponent` keeps its 2.x name and type through accessors, except `audioSummary` on `CommerceAiSearchComponent`, removed in 3.0.0, (for example `results` is still a `ProductCard[]` that can be read and assigned, `showResults` is still a `boolean`, `ngOnDestroy()` is still public), so `@ViewChild` and template-reference users are unaffected. `CommerceAiCartService.openCart()` (and `toggleCart()` when it opens) now re-fetches the cart like the React hook, so the panel never shows a stale cart.

`@commerce-ai-tool/core/client` adds `trackChipGroups`, `selectedFacetChips` (moved from the React package, which keeps re-exporting them), and `audioFromBase64`.

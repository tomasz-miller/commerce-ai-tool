React widget lifecycle and race fixes. `useVoiceSearch` now releases the microphone when the widget unmounts: it stops every `MediaStream` track and the `MediaRecorder`, stops a stream whose `getUserMedia` call resolves after unmount, stops the stream when `new MediaRecorder` throws, ignores a second start while the permission prompt is open, aborts the pending voice and TTS requests, and stops spoken-summary playback (also when a new recording starts or `clearAudioSummary()` is called). `useCommerceAISearch` aborts its in-flight requests and clears its debounce timers on unmount, so a gone widget no longer fires LLM-backed searches. `searchByImage` now uses the same abort signal and request-id guard as text search, so a slower image response no longer overwrites a newer text search or clears its spinner; a superseded result leaves the tracked facet chips alone, and starting an image search forgets clicked chips like a new text search does.

New, additive: `useCommerceAISearch()` returns `beginExternalSearch(): { requestId: number; signal: AbortSignal }` and `isCurrentRequest(requestId): boolean` (typed optional in `UseCommerceAISearchReturn`, like `refine`, but always present), and `useVoiceSearch` accepts both as options. `CommerceAISearch` passes them, so a voice result that arrives after a newer search is dropped (including its transcript) and a newer search aborts the voice request. `clear()` (and typing fewer than two characters) now also makes an in-flight text, image or voice request stale, so an aborted request no longer shows an error or `hasSearched`, and a resolved one no longer reappears after the reset. Without the options `useVoiceSearch` behaves as before apart from the cleanup above. The widget's image-upload input now resets its value after reading the file, so choosing the same image twice searches twice.

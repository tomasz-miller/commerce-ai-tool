Hardening from the final 3.0.0 review. Server: client-supplied `searchTerms`, `sort` and `suggestedFacets` are validated (400 `VALIDATION`) instead of failing with a 500 or fanning out into thousands of query clauses; colliding redacted keys in `defaultLangfuseMask` get their `#2`, `#3` suffixes in linear time; `/tts` honours the request's abort signal (499) and passes it to ElevenLabs; the 402 `PAYMENT_DECLINED` and 400 `MISSING_PRICE` bodies carry fixed messages (the provider text is logged under `CAT_DEBUG=true` only); `createHandlers` is documented as the low-level API without the `Content-Type` check and per-client limiters. Core: a Product Search that is not enabled throws `ProductSearchUnavailableError` (503 `UPSTREAM_UNAVAILABLE`, not a 500); only the documented `InvalidCredentials` error code is a failed sign-in (any other 401, such as a revoked API client, is an upstream error and no longer counts against the per-email login limit); on a shopping-list text query a failed interpret call no longer discards a usable mission; `<attr>Min`/`<attr>Max` filter keys are range bounds only for number attributes of the facet schema; `resolveCommerceAISearchMessages` treats a `null` override like `undefined`; `SearchOrchestratorDeps.facetSchemaStore` is typed with the public type `FacetSchemaStore` (the class stays in `@commerce-ai-tool/core/internal`). React: the camera is released when the widget unmounts or the overlay is closed while the permission prompt is open, and a second open is ignored while one is pending; a refinement cancels a pending debounced search. React and Angular: an Escape that dismisses the autocomplete listbox no longer also closes the cart. Angular: the unused `zone.js` dev dependency is gone.

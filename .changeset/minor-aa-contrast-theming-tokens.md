Widget colours now meet WCAG 2.2 AA (4.5:1) in the light and dark theme, and the theming tokens are documented (GETTING-STARTED, "Theming"). This is a visual change for hosts that use the default colours: the light accent is `#4f46e5` (was `#6366f1`), the light secondary text is slightly darker, filled accent controls (Checkout, Sign in, Capture, Add all, cart badge) draw dark text on the dark theme's accent instead of white, error text is `#b91c1c` in the light theme and `#f87171` in the dark theme (was `#ef4444` in most places), the "added" states (including the mission "Add all" button, which now turns green) and the order-confirmed icon use the new `--cat-success` instead of the accent, and the cart panel follows `--cat-overlay-bg`. New public tokens on `.cat-root`: `--cat-accent-contrast`, `--cat-error`, `--cat-success`, `--cat-cart-panel-bg`, `--cat-z-dropdown`, `--cat-z-panel` and `--cat-z-overlay` (defaults 20, 25 and 40, so stacking is unchanged). Every pre-existing `--cat-*` variable keeps its name. A host that sets its own `--cat-accent` keeps its colour; set `--cat-accent-contrast` as well when white (light) or near-black (dark) text is not readable on it. `pnpm lint` now runs `scripts/check-contrast.mjs`, which fails when a token pair or a text-on-background rule drops below 4.5:1.

Search and login fields use at least 16px on viewports 36rem wide or narrower and on touch devices, so iOS Safari no longer zooms the page on focus. `CommerceAICheckout` reuses one `Intl.DisplayNames` per locale for the country list instead of building one per option on every keystroke. Mission lanes that failed ("Couldn't search this item") or came back empty ("No matching products") are announced through the widget's live region, after the result count; `searchAnnouncement` accepts optional `missionFailedLanes` and `missionEmptyLanes` for this. Docs now state that `CommerceAICheckout`'s busy state relies on React 19 async transitions.

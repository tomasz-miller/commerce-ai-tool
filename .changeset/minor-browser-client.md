`@commerce-ai-tool/core/client` now exports the framework-agnostic browser layer the React and Angular widgets share: `createCommerceAIApiClient` (typed `fetch` client for every host API route; every non-2xx throws `CommerceAIApiError` with a stable `ApiErrorCode`, and a non-JSON error body yields `INTERNAL`), `createCartSessionStore` / `getSharedCartSessionStore` (storage keys, guest id rotation from Web Crypto, stale-snapshot guard, mutation queue, cross-instance sync), `safeStorage`, `recordedAudioFile` (names the voice upload after the recorder's real container, for example `recording.m4a` for `audio/mp4`), `createAudioPlayer`, `messageForError`, and the camera and mission helpers that were duplicated in both widgets. New `CommerceAISearchMessages` keys with English defaults: `microphoneDenied`, `microphoneUnavailable`, `cameraDenied`, `cameraNotFound`, `cameraInUse`, `cameraUnavailable`, `rateLimited`, `resultsCount`. They are optional in the type (an object written against 2.5.0 still compiles; omitted keys read as the English default), and the new `ResolvedCommerceAISearchMessages` (`Required<CommerceAISearchMessages>`) is what `resolveCommerceAISearchMessages` and `DEFAULT_COMMERCE_AI_SEARCH_MESSAGES` return. `getCameraErrorMessage` takes the messages object as an optional second argument; its English defaults for denied access now say how to re-enable the device. The cart and order response types (`CartResponse`, `CartAuthResponse`, `ShippingMethodsResponse`, `PaymentMethodsResponse`, `AuthorizePaymentResponse`, `OrderResponse`, `GetOrderResponse`) move to core. The React and Angular widgets both run on this client.

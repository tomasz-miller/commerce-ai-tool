The React hooks (`useCart`, `useCommerceAISearch`, `useVoiceSearch`, `useCameraCapture`) now run on the shared browser client and cart session store from `@commerce-ai-tool/core/client`; the wire format is unchanged. Every `useCart` on a page shares one guest id, mutation queue and sync bus through `getSharedCartSessionStore()`. Errors shown to shoppers come from the widget `messages` (localized, host overrides apply) instead of the server's developer text; the four hooks accept an optional `messages` option for this, and the widget components pass theirs. `useCommerceAISearch` no longer throws when `sessionStorage` is blocked. A voice upload is named and typed after the recorder's real container (for example `recording.m4a` for `audio/mp4`), and spoken summaries play through one audio element that stops on unmount, with no base64 round-trip. `useVoiceSearch()` returns the new `audioClip: Blob | null` (what the widget replays). New optional message key `cartLoadFailed` (English default) for a failed cart load. `toggleCart` no longer fires its refresh from a state updater, so Strict Mode no longer sends it twice. `useResolvedTheme('auto')` now returns the resolved `light` or `dark` (it was `'auto'`), through `useSyncExternalStore` with a `light` server snapshot; `useTheme` returns the mode as given. The React search hook now sends `facetSelections` for the facet chips the shopper clicked (every clicked group still selected, `categories` included; filters the model echoed back are not chips, and no field is sent without a click): variant-level chips then go to `postFilter`, so a result card can show the master variant instead of the chip's variant (see the faceted navigation trade-off in `docs/SEARCH-PIPELINE.md`). In core, `getSharedCartSessionStore()` on the server now uses a private in-memory storage instead of `globalThis.localStorage`.
